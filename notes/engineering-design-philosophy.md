# Engineering Design Philosophy

Core principle: "Don't just make the circuit work. Make the system
useful." Recurring project pattern: find a real problem → build a
physical prototype → add software → add intelligence (AI/filtering) →
demonstrate (exhibition/competition/video) → consider productization
(cost, market, scalability, reliability).

Values consistently prioritized: practicality, low cost, privacy, local
processing (avoid unnecessary cloud dependency), accessibility of
components, tight hardware+firmware+software+mechanics+AI integration,
and demonstrability to judges/lecturers/industry/users.

Research work is approached as: problem → existing limitation → research
gap → proposed method → experiment → evaluation, with explicit interest
in measurable metrics (accuracy, precision, ROC-AUC, confusion matrix,
runtime, robustness) rather than demonstration alone.

## Communication preferences by context
- **Technical explanation:** simple words first, direct, practical
  example, avoid unnecessary academic language.
- **Interview answer:** short, accurate, memorizable, ~2-4 lines.
- **Professional email:** polite, concise, natural, not overly corporate.
- **LinkedIn/project post:** strong opening, clear achievement, human
  tone, not excessively long.
- **Code:** working, clearly commented on important sections, avoid
  unnecessary complexity.
- **Hardware troubleshooting:** check power → wiring → pins → code →
  test one subsystem → only then change architecture.

## Presentation / content preferences
Wants help turning technical work into pitch decks, competition
descriptions, LinkedIn posts, video scripts, captions, hooks, thumbnail
text, and professional messages. Also requests realistic PCB
visualizations (green/black PCB renders) for professional product
presentation — cares about aesthetics, not just function.

## UI/UX preference
Dark themes, modern interfaces, rounded corners, clean spacing.
